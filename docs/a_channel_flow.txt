//==============================================================================
// a_channel_flow.txt —— a 通道 (放置板物件) 在上銀 HRSS 手臂端要寫哪些指令
//
// 達明是在 TM Flow 拉圖元, 上銀是在教導器上寫指令。這份文件就是原本達明版
// (docs/tm_legacy/a_channel_flow_tm.txt) 的逐段對照, 邏輯、時序、接線腳位完全相同,
// 只有「怎麼寫」不同。
// b 通道 (隨機板物件) 用 docs/hiwin_flow_v1.hrb (不需修改, 只改裡面的 IP)。
//
// 本文件所有數字都來自樹莓派端程式, 改程式就要同步改這裡:
//   3-bit 編碼表 / 失敗碼 / 保持秒數  → pi_gpio_controller.py 頂端 IO_CODES、FAIL_CODE、HOLD_SEC、FAIL_HOLD_SEC
//   辨識 (投票) 秒數                    → main_contest.py 的 VOTE_SEC
//   $DI[] / $DO[] / $RO[] 語法          → HIWIN Robot Software Manual 3.3 (C25UC212-2508) 6.5.1 p.242
//   起始姿態與電爪開合一次              → 2025 題目卷「評分規範」(2026 題目卷出來後請再對一次)
//
// a 通道只判斷【顏色】, 不判斷形狀。
//==============================================================================


//===== 賽前接線 (BCM 編號, 見 pi_gpio_controller.py 的 RELAY_PINS / READY_PIN) =====
//
//   ★ 上銀的 IO 從 1 起算 ($DI[1]~$DI[24]、$DO[1]~$DO[24], 手冊 6.5.1 p.242),
//     達明從 0 起算。所以達明版的 DI0~DI4 / DO0 在上銀全部 +1。
//
//   手臂 $DO[1]      ──▶ 樹莓派 GPIO26   (ready: 通知樹莓派開始辨識)      ← 達明 DO0
//   樹莓派 R1 (17)   ──▶ 手臂 $DI[1]     (觸發: 編碼有效, 保持 HOLD_SEC = 7 秒) ← 達明 DI0
//   樹莓派 R2 (27)   ──▶ 手臂 $DI[2]     ┐                                 ← 達明 DI1
//   樹莓派 R3 (22)   ──▶ 手臂 $DI[3]     ├ 3-bit 顏色編碼                   ← 達明 DI2
//   樹莓派 R4 (23)   ──▶ 手臂 $DI[4]     ┘                                 ← 達明 DI3
//   光電感測器       ──▶ 手臂 $DI[5]     (深度, 不經樹莓派; 腳位依現場; 題目沒有深度判斷就不用接)
//
//   夾爪: 上銀末端訊號是 $RO[1]~$RO[8] (手冊 6.5.1 p.242)。本文件用 $RO[1] 當「夾/放」,
//         對應達明的 IO["EndModule"].DO[1]。實際接在哪個點位以現場接線為準;
//         若接在控制箱就改成對應的 $DO[n]。


//===== DI 解碼表 (預設值; 選手若改了 IO_CODES / FAIL_CODE, 這張表要跟著改) =====
//   $DI[1]  $DI[2] $DI[3] $DI[4]   意義
//     1       0      0      1      red
//     1       0      1      0      blue
//     1       0      1      1      green
//     0       1      1      1      【辨識失敗】$DI[1] 不會變高, 手臂靠等待逾時後讀 $DI[2..4] 得知
//     0       0      0      0      待命 / 訊號已收回
//
//   ※ 失敗碼 1 1 1 是 IO_CODES 沒用到的組合, 所以就算 $DI[1] 那條線接觸不良,
//     也不會把某個顏色誤讀成失敗。新增顏色時不要用 1 1 1。


//===== 時序 (以手臂拉高 $DO[1] = ready 的瞬間為 t = 0) =====
//   樹莓派: t=0 開始投票 VOTE_SEC = 3 秒 (每一幀看到的最大物件顏色投一票)
//   成功: t=3 先擺好 R2 R3 R4 → t=4 R1 拉高 → 保持 HOLD_SEC = 7 秒 → t=11 全部關閉
//   失敗: t=3 R2 R3 R4 = 1 1 1, R1 不拉高 → 保持 FAIL_HOLD_SEC = 10 秒 → t=13 全部關閉
//
//   手臂等 $DI[1] 的逾時設 8 秒:
//     成功時 t=4 就通過; 失敗時 t=8 逾時, 此時失敗碼還在 (到 t=13), 讀 $DI[2..4] = 1 1 1 即知失敗。
//   不可設 15 秒: 失敗碼 t=13 已收回, 逾時後只讀到全 0, 分不出「失敗」和「樹莓派沒回應」。


//===== 每一件 a 物件要寫的指令 (對照達明版的 1~10 步) =====
//
//  下面的變數在主程式開頭宣告一次就好 (手冊 8.2, 變數宣告 INT / BOOL):
//      INT nCode        ; 3-bit 解出來的數字 1~7
//      INT nTick        ; 等待計數
//      BOOL bGot        ; 有沒有等到 $DI[1]
//
//  ┌ 1. 移到題目區 2 的該物件夾取點 (預教點位; FINE=2 才做到位檢查, 手冊 8.7.2 p.407)
//  │      PTP P1 FINE=2 Vel=20% Acc=50% TOOL[0] BASE[0]
//  │
//  ├ 2. 關夾爪, 等 0.3 秒讓夾爪確實夾住
//  │      $RO[1] = TRUE
//  │      WAIT SEC 0.3
//  │
//  ├ 3. 移到【固定檢測位】
//  │      PTP P3 FINE=2 Vel=20% Acc=50% TOOL[0] BASE[0]
//  │    ※ 此點要讓物件完整入鏡且夠大 (面積要超過該顏色 profile 的 min_area)
//  │    ※ 教這個點位時, 樹莓派同時跑 io_test.py 看畫面, 直到出現綠框、左上角 seen= 顯示正確顏色
//  │    ※ 用 FINE=2 的另一個理由: FINE=2 不會預讀下一行 (手冊 8.7.2), 確保第 4 步是「到位之後」才拉 ready
//  │
//  ├ 4. 拉高 ready
//  │      $DO[1] = TRUE
//  │    → 樹莓派終端印「[a] 收到 ready, 投票 3 秒」
//  │
//  ├ 5. 等 $DI[1] == TRUE, 最多 8 秒 (理由見上面「時序」)
//  │      bGot = FALSE
//  │      nTick = 0
//  │      WHILE bGot == FALSE
//  │        WAIT SEC 0.1
//  │        IF $DI[1] == TRUE THEN
//  │          bGot = TRUE
//  │        ENDIF
//  │        nTick = nTick + 1
//  │        IF nTick >= 80 THEN
//  │          bGot = TRUE
//  │        ENDIF
//  │      ENDWHILE
//  │    (另一種官方寫法: WAIT FOR $DI[1] == TRUE TIMEOUT(8, LABEL), 手冊 6.31.1 p.313;
//  │     逾時會跳到 LABEL 標籤, 要自己用 GOTO 跳回來, 流程較繞, 所以本文件用上面的輪詢寫法。)
//  │
//  ├ 6. 把 $DI[2] $DI[3] $DI[4] 三個 bit 讀成一個數字 (WAIT SEC 0 先停止預讀, 手冊 8.1.2 p.371 提示)
//  │      WAIT SEC 0
//  │      nCode = 0
//  │      IF $DI[2] == TRUE THEN
//  │        nCode = nCode + 4
//  │      ENDIF
//  │      IF $DI[3] == TRUE THEN
//  │        nCode = nCode + 2
//  │      ENDIF
//  │      IF $DI[4] == TRUE THEN
//  │        nCode = nCode + 1
//  │      ENDIF
//  │    → 成功時 ($DI[1] == TRUE) nCode 就是 IO_CODES 的值: 預設 1=red 2=blue 3=green
//  │
//  ├ 6-1. $DI[1] 沒等到 (逾時) 的情況, 看 nCode:
//  │      == 7 (1 1 1) → 辨識失敗: 建議把物件稍微轉個角度 / 重新對正鏡頭後, 回到第 4 步再試一次;
//  │                     或直接放到暫置區跳過。
//  │      == 0 (0 0 0) → 樹莓派沒有回應: 檢查 main_contest.py 是否還在跑、$DO[1] → GPIO26 接線。
//  │
//  ├ 7. 讀光電感測器 → 深度分支 (題目沒有深度判斷就省略本步)
//  │      IF $DI[5] == TRUE THEN
//  │        ...
//  │      ENDIF
//  │
//  ├ 8. 放下 ready
//  │      $DO[1] = FALSE
//  │    ※ 不可省略: 樹莓派要看到 ready 回到 0 (WAIT_RELEASE 狀態) 才會接受下一件的觸發
//  │
//  ├ 9. 依顏色 (和深度) 移到題目區 3 對應點位, 用 SWITCH 最清楚 (手冊 8.6.7 p.400)
//  │      SWITCH nCode
//  │        CASE 1
//  │          PTP P11 FINE=2 Vel=20% Acc=50% TOOL[0] BASE[0]   ; red 的放置點
//  │        CASE 2
//  │          PTP P12 FINE=2 Vel=20% Acc=50% TOOL[0] BASE[0]   ; blue 的放置點
//  │        CASE 3
//  │          PTP P13 FINE=2 Vel=20% Acc=50% TOOL[0] BASE[0]   ; green 的放置點
//  │        DEFAULT
//  │          USER_ALARM[1]                                     ; 失敗或沒回應, 在教導器上會跳警報 (手冊 6.19.2 p.292)
//  │      ENDSWITCH
//  │    ※ 只有 bGot == TRUE 且 nCode 在 1~6 時才該放; 逾時 (nCode = 7 或 0) 走 DEFAULT 不放。
//  │
//  └ 10. 開夾爪, 沿 Z 抬起離開 (手冊 6.2.2.3 p.229 LIN_REL)
//         $RO[1] = FALSE
//         WAIT SEC 0.3
//         LIN_REL {Z 60} FINE=2 Vel=100mm/s Acc=50% TOOL[0] BASE[0]
//
//  → 接下一件 (下一件是 b 就呼叫 hiwin_flow_v1(), 見下面「整體流程範例」)


//===== 整體流程範例 (假設題目要求 5 件: a, b, b, a, b) =====
//
//   ;----- 主程式開頭 -----
//   EXT hiwin_flow_v1()              ; 宣告外部副程式 (廠商範例 Main_TCP.hrb 的寫法; 檔名 = DEF 名稱, 手冊 8.10.2 p.413)
//   INT nCode
//   INT nTick
//   BOOL bGot
//   SET_OVERRIDE_SPEED 30            ; 總體速度倍率 1~100 (手冊 6.17.1 p.281); 調機先用低速
//   PTP P0 FINE=2 Vel=20% Acc=50% TOOL[0] BASE[0]     ; 起始姿態 (2025 題目卷評分規範)
//   $RO[1] = TRUE                    ; 電爪開合一次 (評分規範要求)
//   WAIT SEC 0.5
//   $RO[1] = FALSE
//   WAIT SEC 0.5
//
//   ;----- 第 1 件: a -----   上面 1~10 步的指令
//
//   ;----- 第 2 件: b -----
//   hiwin_flow_v1()                  ; 送 GET, 樹莓派回 {x,y} (mm × 1000), 副程式移到物件正上方 Z_SAFE
//   LIN_REL {Z -30} FINE=2 Vel=100mm/s Acc=50% TOOL[0] BASE[0]   ; 選手自己接: 下降 (數值依夾取高度)
//   $RO[1] = TRUE                    ; 夾取
//   WAIT SEC 0.3
//   LIN_REL {Z 30} FINE=2 Vel=100mm/s Acc=50% TOOL[0] BASE[0]    ; 抬起
//   PTP P21 FINE=2 Vel=20% Acc=50% TOOL[0] BASE[0]                ; 題目區 3: PICK_ORDER 第 1 個顏色的放置點
//   $RO[1] = FALSE                   ; 放開
//   WAIT SEC 0.3
//   LIN_REL {Z 60} FINE=2 Vel=100mm/s Acc=50% TOOL[0] BASE[0]
//     放置點靠順序決定: 第 N 次呼叫 hiwin_flow_v1() 一定是 PICK_ORDER 的第 N 個顏色
//     (樹莓派每收一次 GET 就前進一格, 找不到物件也前進), 所以每次呼叫後面直接接該顏色的放置點位即可。
//     樹莓派回 {0,0} (沒有可給的) 時副程式不會移動, 手臂會停在原地做接下來的下降/夾取 —— 正式比賽
//     PICK_ORDER 寫滿實際件數就不會發生。
//
//   ;----- 第 3 件: b -----   同上, 放置點換 PICK_ORDER 第 2 個顏色 (P22)
//   ;----- 第 4 件: a -----   1~10 步
//   ;----- 第 5 件: b -----   同上, 放置點 P23
//
//   PTP P0 FINE=2 Vel=20% Acc=50% TOOL[0] BASE[0]     ; 回起始姿態
//
//   b 通道的夾取順序寫在 main_contest.py 的 PICK_ORDER; 用完會回 {0,0}。
//   a 與 b 的先後由主程式裡指令的排列決定。


//===== 賽前用 io_test.py 驗接線 (樹莓派端, 手臂不必先寫好程式) =====
//   python3 io_test.py
//   1~9  送出 IO_CODES 裡第 1~9 個顏色的訊號 (預設 1=red 2=blue 3=green; 不看相機, 純測接線)
//   f    送出失敗碼 (R1 不拉高, R2 R3 R4 = 1 1 1)
//   0    全部繼電器關閉
//   r    把相機目前看到的顏色送出去 (和比賽動作一樣)
//   q    離開
//   畫面左上角: seen = 目前看到的顏色, ready = GPIO26 電位, last IO = 最後送出的訊號
//   啟動時終端會列出數字鍵對應表, 並提醒 IO_CODES 裡有哪些顏色在 vision_profiles.json 還沒存。
//   手臂端在教導器的 IO 監視畫面看 $DI[1]~$DI[4] 有沒有跟著亮, 就能確認接線和解碼表。


//===== 常見問題 =====
//
// Q: $DI[1] 一直等不到?
// A: 看樹莓派終端有沒有印「[a] 收到 ready」。
//    沒印 → $DO[1] 到 GPIO26 的接線或電位有問題 (跑 io_test.py, 左上角 ready= 會即時顯示)。
//    有印但送了失敗碼 → 終端會印「沒看到任何 IO_CODES 裡的顏色」: 物件太小 (min_area)、
//    HSV 沒調好, 或顏色名和 IO_CODES 對不上。
//
// Q: 判到錯的顏色?
// A: 兩個顏色的 HSV 範圍重疊。用 vision_tuner.py 依現場燈光重調 (按 n 切換已存顏色),
//    再用 io_test.py 確認 seen= 顯示正確。
//
// Q: b 的 hiwin_flow_v1.hrb 要改嗎?
// A: 只改裡面 COPEN 那一行的 IP。樹莓派回 {x,y} (mm × 1000), 副程式除 1000 當手臂座標。
//    放置點不靠回覆內容, 靠呼叫次數對 PICK_ORDER (見上面「整體流程範例」)。
//
// Q: 手臂逾時後讀到 $DI 全是 0?
// A: 等待秒數設太長, 失敗碼已經收回。改成 8 秒 (nTick >= 80)。
//
// Q: 達明版接線圖上寫 DI0~DI3, 上銀怎麼對?
// A: 全部 +1: DO0→$DO[1], DI0→$DI[1], DI1→$DI[2], DI2→$DI[3], DI3→$DI[4], DI4→$DI[5]。
//    接線本身不用動, 只是編號方式不同。
